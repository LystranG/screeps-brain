# External Integrations

**Analysis Date:** 2026-05-03

## APIs & External Services

**Screeps Deployment API:**
- Screeps official MMO server - Receives bundled bot code from Rollup deploy scripts.
  - SDK/Client: `rollup-plugin-screeps` configured in `rollup.config.js`.
  - Auth: `token` field in `screeps.json` destination objects for `main`, `season`, and `sim`.
  - Destinations: `main`, `season`, and `sim` keys in `screeps.json` and `screeps.sample.json`.
  - Upload trigger: `npm run push-main`, `npm run push-season`, `npm run push-sim`, and corresponding watch scripts in `package.json`.
  - Branch selection: `branch` field in each destination object in `screeps.json`.

**Screeps Private Server:**
- Screeps private server - Optional deploy target for testing or private play.
  - SDK/Client: `rollup-plugin-screeps` configured in `rollup.config.js`.
  - Auth: `email` and `password` fields in the `pserver` destination object in `screeps.json`.
  - Network fields: `protocol`, `hostname`, `port`, and `path` in `screeps.json`.
  - Destination: `pserver` key in `screeps.json` and `screeps.sample.json`.
  - Upload trigger: `npm run push-pserver` and `npm run watch-pserver` in `package.json`.
  - Server requirement: `README.md`, `docs/getting-started/deploying.md`, and `docs/in-depth/troubleshooting.md` document that private-server uploads require private-server authentication support such as `screepsmod-auth`.

**Screeps Runtime API:**
- Screeps in-game globals - The bot reads and mutates game state at runtime.
  - SDK/Client: ambient global API typed by `@types/screeps` from `package.json`.
  - Auth: Not applicable inside runtime; execution is controlled by uploaded account branch.
  - Usage: `src/main.ts` uses `Game.time`, `Game.creeps`, and `Memory.creeps`; `src/utils/ErrorMapper.ts` uses `Game.rooms` and Screeps console output.

**Developer Documentation Links:**
- GitHub/GitBook/Screeps docs links are present in `README.md` and `docs/`, but the application code does not call those services.
  - SDK/Client: Not applicable.
  - Auth: Not applicable.

## Authentication & Identity

**Auth Provider:**
- Screeps account token authentication for official destinations.
  - Implementation: `rollup.config.js` selects `require("./screeps.json")[process.env.DEST]` and passes it to `screeps({ config: cfg, dryRun: cfg == null })`.
  - Credential fields: `token` in `screeps.json` for `main`, `season`, and `sim`.
  - Sample config: `screeps.sample.json`.
  - Secret handling: `.gitignore` ignores `screeps.json`.
- Screeps private-server account authentication for `pserver`.
  - Implementation: same `rollup-plugin-screeps` path through `rollup.config.js`.
  - Credential fields: `email` and `password` in `screeps.json` for `pserver`.
  - Server-side dependency: docs reference private-server authentication support such as `screepsmod-auth`.

## Monitoring & Observability

**Error Tracking:**
- External error tracking service: None detected.
- Runtime error mapping is local/in-game:
  - `src/utils/ErrorMapper.ts` wraps the exported loop and maps bundled stack traces back to TypeScript source positions using `source-map`.
  - `src/main.ts` exports `loop = ErrorMapper.wrapLoop(...)`.

**Logs:**
- Screeps console logging through global `console.log`.
- `src/main.ts` logs current game tick with `Game.time`.
- `src/utils/ErrorMapper.ts` logs source-mapped errors as HTML-formatted red text in the Screeps console.
- Build-time logging in `rollup.config.js` prints a dry-run message when `DEST` is omitted.

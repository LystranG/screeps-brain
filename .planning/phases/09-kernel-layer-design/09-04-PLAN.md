**Section 1: 总体原则（D-12）**
State the governing principle: "每 tick Refresh 阶段完全重建，无状态，bug 范围 ≤ 1 tick（D-12）". Explain why: Screeps Game.creeps is a fresh object each tick, creep assignment to TaskForces is stored in Creep.memory (persistent), so the index is reconstructed from authoritative source (memory) on every refresh. This eliminates stale-state bugs at the cost of O(n) work per tick, which is acceptable for 100–300 creeps.

Compare to the alternative (cross-tick incremental updates): "跨 tick 增量更新的替代方案引入脏状态风险——creep 死亡、TaskForce 解散、memory 被手动修改都会导致索引不一致，需要复杂的清理逻辑。完全重建消除了这类问题。"

**Section 2: HighCommandCache 数据结构（D-13、D-14）**
Show the internal `HighCommandCache` interface. This is domain-private to `HighCommand.ts` (NOT exported from barrel, NOT in shared/interfaces/). Place it in `src/highCommand/HighCommand.ts` or `src/highCommand/types.ts`:

```typescript
// src/highCommand/types.ts（HighCommand 域私有类型，不通过 barrel 导出）

/**
 * HighCommand 全局 Cache：每 tick Refresh 阶段完全重建的反向索引。
 * 正向查询：TF ref → creep 名称列表 / Garrison name → creep 名称列表。
 * 不维护 creep → TF 的反向映射（D-14）。
 */
export interface HighCommandCache {
  /** TaskForce ref → 该 TF 管辖的 creep 名称列表（D-13）*/
  creepsByTaskForce: Record<string, string[]>;
  /** Garrison name（房间名）→ 该 Garrison 管辖的 creep 名称列表（D-13）*/
  creepsByGarrison: Record<string, string[]>;
}

/** Cache 初始值（空索引，Build 阶段初始化，Refresh 阶段重建）*/
export const EMPTY_CACHE: HighCommandCache = {
  creepsByTaskForce: {},
  creepsByGarrison: {}
} as const;
```

Explain data structure choice (D-12 open question resolution): Use `Record<string, string[]>` / plain object rather than `Map<string, string[]>`. Reason: Screeps `for...in Game.creeps` already yields string keys; plain object requires no type conversion; consistent with Screeps Memory patterns; Map instances have no benefit in the Screeps tick model where the cache is fully rebuilt each tick.

**Section 4: rebuildCache() 重建算法（D-12、D-13）**
Show the complete implementation:

```typescript
/**
 * 完全重建 Cache 索引：遍历 Game.creeps，按 memory.ref 和 memory.garrison 分组。
 * 每 tick Refresh 阶段调用一次，无状态，bug 范围 ≤ 1 tick（D-12）。
 */
private rebuildCache(): void {
  // 重置为空索引（完全重建，不复用上 tick 状态）
  this.cache = {
    creepsByTaskForce: {},
    creepsByGarrison: {}
  };

  // Game.creeps 是 Record<string, Creep>，必须用 for...in 遍历（非数组，不适用 prefer-for-of 规则）
  for (const name in Game.creeps) {
    const creep = Game.creeps[name];
    const ref = creep.memory.ref as string | undefined;
    const garrisonName = creep.memory.garrison as string | undefined;

    // 按 TaskForce ref 分组（D-13）
    if (ref !== undefined) {
      (this.cache.creepsByTaskForce[ref] ??= []).push(name);
    }

    // 按 Garrison name 分组（D-13）
    if (garrisonName !== undefined) {
      (this.cache.creepsByGarrison[garrisonName] ??= []).push(name);
    }
  }
}
```

Add explanatory notes:
- `??=` (nullish coalescing assignment) initializes the array if not present — SPEC-02 compliant, ES2021
- `for...in` over `Game.creeps` is the standard Screeps pattern; ESLint `prefer-for-of` applies only to arrays
- Dead creeps: `Game.creeps` only contains living creeps, so dead creeps are automatically excluded
- Orphaned memory: creeps with stale `memory.ref` (TF no longer exists) are still grouped; the TF is responsible for cleanup in its own lifecycle

**Section 7: 性能说明**
Time/space complexity analysis:
- `rebuildCache()` 时间复杂度: O(n)，n = 存活 Creep 数量（通常 100–300）
- 每 tick 遍历 `Game.creeps` 的成本: 与 Creep 数量线性，不与 TaskForce 或 Garrison 数量相关
- 查询方法 `getCreepsByTaskForce` / `getCreepsByGarrison`: O(1) hash lookup
- 内存占用: O(n) 字符串引用（每个 Creep name 存储一次，不复制 Creep 对象）

Performance acceptance table:

| 场景 | Creep 数 | rebuildCache() 预估 CPU | 可接受 |
|------|---------|------------------------|--------|
| 小型基地（RCL 3-5） | 20–50 | < 0.1 ms | ✅ |
| 中型基地（RCL 6-7） | 50–150 | < 0.3 ms | ✅ |
| 全盛基地（RCL 8 + outpost）| 150–300 | < 0.8 ms | ✅ |
| 极限（多 Garrison 300+） | 300+ | < 2 ms | ✅（可接受，远低于 20 ms limit）|

**Section 8: 禁止模式**
Four forbidden patterns with ❌/✅ code blocks:
1. Cache 跨 tick 复用 (D-12) — retaining last tick's cache instead of rebuilding ❌
2. 维护反向索引 (D-14) — `creepsByName: Record<string, string>` (creep → TF) ❌ (O(1) from memory.ref is sufficient)
3. TaskForce 直接 import HighCommand (SPEC-03) — `import { HighCommand } from "highCommand"` in TaskForce ❌ vs constructor injection of `ITaskForceRegistry` ✅
4. 在 barrel 导出 HighCommandCache (SPEC-04 最小化 API 面) — `export { HighCommandCache }` in `highCommand/index.ts` ❌ vs domain-private in `types.ts` ✅
